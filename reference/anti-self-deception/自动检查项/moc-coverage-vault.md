## ⭐ 2026-08-15 用户裁定：扫描范围收窄到**已进版本库的文件**

**改的是范围，不是判据。** 页面清单现在取自 `git ls-files`，而不是遍历工作副本。
后果：一页**写好但还没提交**时不再算欠债，它被列进一行「尚未提交、因而未纳入检查」的清单
（**照常打印，绝不静默丢掉**——一个从计数里消失的东西，正是自动检查悄悄停止覆盖某类问题的样子）；
**它的作者一提交，它当场进入检查范围**。

**为什么改**：这个检查全库跑、不分窗口，而 vault 是四个以上会话共写的同一个工作副本，
于是**谁先收尾，谁就把别人半写完的页面当成自己的欠债**。2026-08-15 一个下午实测三次，
每次被拦的会话都**无法修**——产物是别人的，而对方正在写；三次里有两次是靠对方恰好及时补上才解掉，
那是运气不是机制。收窄范围不削弱这个检查真正要防的东西：它要抓的是
「页面**已经在库里**、却没有任何读者入口」，而未提交的文件按定义还不在库里、还在作者手上。

**新增开关**：`--all-files` 恢复旧的遍历工作副本行为，供需要连在途文件一起看时使用。

**自检已补两例并实跑通过**：在临时 git 仓里，已提交且未覆盖的页面**照常报红**，
未提交且未覆盖的页面**列为待提交**；`--all-files` 下两者都报红。
（原有三例——必报、命名后不报、别名/小标题/带路径三种写法不误报——全部保持通过。）

⚠️ **同伴窗口指出的一个真实反面，值得记住**：不要因此把「报红」当成噪音去压制。
它当天的原话大意是——「等对方静默一段时间再报」这种折中会把**「他还在写」**和
**「他写完就走了、忘了收尾」**合并成同一个观测，而后者恰恰是最该被抓住的。
本次改动没有落入这个陷阱：未提交页面**每次都打印**，只是不再让别人的在途工作使自己的收尾失败。
⛔ **报红是对的；为了消红而提前登记或提前提交才是错的**——那会造出
「学科地图说有这一页、库里没有」的假账。

## 多窗口共享工作副本下怎么分诊（2026-08-15 加，⛔ 这不是豁免）

这个检查是**全库跑的、不分窗口**，而 vault 是多个会话共写的同一个工作副本。
后果：**谁先收尾，谁就会撞上别人还没写完的产物**，而报出来的红**不一定是自己欠的债**。
2026-08-15 实测两次，两个方向各一次：本窗口被别窗口的在途新页拦下；别窗口也被本窗口的在途卡拦下。

**分诊判据是文件状态，不是文件类别：**

```bash
git -C ~/ObsidianVault status --porcelain "<报出来的那一页>"
```

- 输出 `??`（未跟踪）或 ` M`（已改未提交）→ **多半是别的窗口正在写**。
  按跨窗口约定**把发现交给该页的主人，不要自己动手**——它多半会把新页与学科目录条目
  放在同一次提交里，插手会撞车。交出去之后继续做自己的事，对方挂好后重跑即可。
- 输出为空（该页已在版本库里）而检查仍报它走不到 → **这才是真欠债，当场修**。

**只按「这类文件归谁」判归属是不够的**：同一类文件里也可能混着自己刚写完还没提交的东西。
两条合起来才判得准。

⛔ **以上不构成豁免，检查的判定一个字没改**：红就是红，别人的债也得等它清了才算过。
这里只是告诉收尾的人**该去找谁**，免得把别人的在途产物当成自己的欠债去改，
反而制造冲突。
⚠️ 停止门的提示语里有一句「确属豁免场景则按该 goal 文件写明的豁免标记规则打标」——
**本检查从来没有写过豁免标记规则**（`retire-when: 永不`）。那句提示是通用模板，
读到它别去找一个不存在的规则。
