交接便条检查 (2026-08-15 用户要求「所有的窗口我都希望加个自动交接的机制」+「要保证这个有效」)。

**要解决的问题**: 多个窗口长期并行干活, 会话会被压缩、会被关掉、额度会用完。
压缩本身不丢东西 —— **丢的是没写进文件的东西**。所以每个长期窗口留一份便条:
我是谁、任务书在哪、做到哪、被打断时下一步做什么, 让压缩后的自己或接手的新窗口
一分钟内回到状态。

**为什么要装成自动检查而不是写份文档**: 靠自觉维护的文档必然过期, 而**过期的交接
便条比没有更坏** —— 接手的人会信它。所以这个检查比对便条时间戳与窗口存活状态:
窗口还在跑而便条超过 3 小时没更新 = 报红; 长期窗口(名字含 concept/paper/book/read/
audit/prop/seed/chain)完全没有便条 = 报红; 便条缺四个必填小节或时间戳解析不了 = 报红。

**便条放哪**: `~/.claude/handoff/<窗口名>.md`。格式与四个必填小节见脚本 docstring,
范例见 `~/.claude/handoff/cmix-read.md`。⚠️ 「做到哪了」一节**只放指向已有状态源的
指针, 不复制内容** —— 复制品会和真源打架, 而两份打架的记录比一份过期的更难查。

**⭐ 2026-08-26 改判据(用户从 tmux 换到 herdr)**: 「哪些窗口在跑」不再问 tmux, 改问
herdr 的 agent 列表, 探测口统一在 `~/.claude/scripts/live_windows.py`(herdr 问不到才
退回 tmux)。⛔ 换管理器那天暴露的缺陷值得记: tmux 会话没关, 里面留着一批**同名的空壳
窗口**(窗口在、Claude 不在), 于是这道检查一边对着死壳子喊「便条过期」, 一边完全看不见
herdr 里真正在跑的八个窗口 —— **两头都错, 却照常打印出一份看起来正常的报告**。
根因是拿「窗口这个容器存不存在」代替「里面有没有 agent 在干活」; herdr 那条直接列
agent, 顺带把插件开的 tab 和空 shell 排除掉。**窗口名 = herdr 里 tab 的标签**, 便条文件名
必须与之逐字相同(同日据此把 j-<project-B>/n14-probe/concept7/papers6 改名为 J/DOTD/concept/paper)。

**报红后怎么办**: 便条过期就更新它(顺手确认那个窗口是不是已经停了); 窗口没便条就
补一份。⛔ 不要为了让检查转绿而写空壳便条 —— 便条的用途是让人接得上, 写成空的等于
把「无法接手」这件事藏起来。
