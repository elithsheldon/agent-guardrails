欠着的链接检查 (2026-08-15 加, 由读论文的窗口自己提出的缺口)。

**要解决的问题**: 新分工下, 读论文的窗口遇到缺概念页时不再自己建, 而是请概念窗口写。
请求发出到页面落地之间有一段真空, 这段时间卡里按房规写**纯文字**(wikilink 必须指向
已存在的文件, 否则链接检查当场判 dangling)。页面落地后要回来把裸文字包成链接——
**而这个动作在此之前只挂在某个会话的记忆里**。会话会被压缩、会被关掉, 记忆不是机制。

**advisory, 不是硬门**: 链或不链是判断不是机械可判的事。房规仍然适用——只链每一节的
首次承重提及; 泛指名词/提示框标签/标题/被引书名不链; ⛔ 绝不为塞链接改写句子。
**「不链」是正常结论。** 包链接后跑 `check_link_only_diff.py` 证明正文一字未动。

**装上时 RED 测试抓出本脚本自己的两个 bug**(两个都会造成一片假绿, 值得记住):
1. **按「git 记的新增路径还在不在」过滤, 会把移动过的页全部滤掉** —— 概念窗口当天
   把一批页移进了新学科夹, 于是 git 记的路径全不存在。改成**按页名找它现在在哪**。
2. **「卡里已有一处链上就跳过整张卡」是错的** —— 新房规要的是**每一节**的首次承重
   提及都链, 而这条产线上最常见的形态恰恰是「一处链了、另一处还是当初的裸文字」。
   种入的缺陷正是被这个 bug 吃掉的。

两个 bug 修完后, 种入的缺陷被准确抓到、恢复后又正确消失。
