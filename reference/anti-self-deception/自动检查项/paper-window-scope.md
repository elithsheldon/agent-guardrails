读论文的窗口有没有越界去写概念页。用户 2026-08-23 要求「硬性规定」时装的。

守的边界是房规 feedback_paper_window_reads_papers_only.md, 用户 2026-08-15 原话:
「以后记得你只读论文就好了, 遇到概念直接扔给伙伴」。⛔ 那条房规立了八天, 2026-08-23 照样被
越过两次: 总控派活时要求「先建两张概念页再动卡」, 读论文窗口照做并真建了一页, 直到用户第二次
开口才停。所以缺的不是规矩, 是一道在动手那一刻挡住的检查 —— 这条边界恰恰在「手上正好有材料、
写起来很顺」的时候最不容易想起来。

⭐ 为什么两个人同时越界, 这一段是支点: 两个问题被合并成了一个。「这一页该照书写还是照论文写」
是内容问题, 「这一页归哪条线写」是分工问题。当时的推理是「架上没有这本书, 所以只能照论文写,
所以归读论文的窗口写」—— 前半句是内容判断, 后半句是分工判断, 而中间那个「所以」不成立。
而房规给的理由当天又应验一次: 读论文的窗口手上只有那一篇文献, 写出来的概念解释必然比照着整本
书写的薄; 那次「架上没有书」的判定, 剥掉一个限定词之后变成五本书、其中一本有整整一节。

判据不问「我打算写什么」, 问「这个窗口实际在版本库里新建了哪些文件」—— 后者是窗口改不动的量。
Papers/ 下的新文件是论文卡(合法), _meta/ 下的是记录与登记(合法), 其它学科目录下的新文件是
概念页(越界)。⚠️ 已存在页面上的修改不算越界: 补链接、改错、退掉失效说法都是论文卡逼出来的
正当改动, 房规禁的是「建」不是「碰」。

三支都真撞过, 不是断言: 把那张被撤的概念页放回去 → 报 1 并指名文件; 建一张论文卡 → 退出 0;
无新建文件 → 退出 0 并明说「什么都没检查到」而不是报「没问题」。
retire-when: 永不 (它守的是两条线之间的分工)。

实际发生的事：它对着 `daily/2026-08-26.md` 与 `daily/2026-08-27.md` 报「读论文窗口越界」，

实验记录；`daily/` `weekly/` 还是 CONVENTIONS 里明文写着的内容流。缺陷由 concept 窗口发现并
交来，我逐条核实后接手改的（同一族错误＝拿一个便于取得的代理量去代表它代表不了的状态）。
