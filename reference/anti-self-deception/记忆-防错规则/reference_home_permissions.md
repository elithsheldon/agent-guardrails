## ⭐ umask 为什么必须放在 .bashrc 最顶上

`.bashrc` 第 20、34 行有 `case $- in *i*)` —— 只对**交互式** shell 生效的分支。
而训练任务是 `ssh + setsid` 非交互式拉起的：放在那之后，真正在写实验结果的进程就管不到。
放第 1 行后实测三台远端 `ssh host 'umask'` 都返回 0077。

⚠️ **已经在跑的进程继承的仍是旧的 022**，会继续写 644 的新文件，直到它们重启 ——
这一条无法补救，只能靠外层那道 `drwx------` 兜住。

## ⛔ 四个会把结论弄错的陷阱（都是这次实测踩到的）

1. **`pgrep -f "<字符串>"` 会匹配到自己这条命令行**。我用它判断后台 chmod 的进度，
   连报两次「还在跑」，其实进程早就结束了。判后台任务是否完成要用**完成标记文件**
   （`... && echo DONE > /tmp/x.done`），别用命令行文本去匹配。
2. **符号链接的权限位永远是 `lrwxrwxrwx`，`chmod` 对它是静默无操作**。
   扫描时会剩下上万条 `777 l`，⚠️ 那不是漏改 —— 内核访问时看的是目标文件的权限。
   统计「还有多少对外可读」时必须加 `! -type l`，否则数字全是假的。
3. **⛔ 按目录名手工列举来分批改，必漏**。我列了 20 多个目录，结果 `.TinyTeX`
   `vaults` `anon_release` `paper_pdfs` `.rustup` 等一万条全没改到。
   正确做法是**按事实找**：`find ~ -xdev ! -type l \( -perm -o+r -o -perm -g+r ... \)`
   —— 让「还带着权限位」这个事实本身来决定改哪些，而不是让我的记忆决定。
4. **`pgrep -c` 数到 0 时退出码是 1**，写成 `pgrep -c ... || echo "连不上"` 会把
   「一个都没有」误报成「机器连不上」。这两件事的处置完全不同（前者要查任务是不是跑完了，
   后者要查网络），混起来会查错方向。

## ⚠️ 收紧不是一次性的：老 shell 里 umask 还是旧的

`umask 077` 只对**写进 .bashrc 之后新开的** shell 生效。当天 09:39 就复现了一次：
另一个更早启动的 Claude 会话按新的作业隐藏规矩往 venv 里 `pip install setproctitle`，
一口气产生 1159 个 644/755 的新文件。**不是漏改，是那个 shell 的 umask 仍为 022。**

所以：**改完权限之后新出现的对外可读文件，先看时间戳再下结论** ——
晚于收紧时刻的一律是这个原因，不是扫描漏了。重扫一遍即可：

```bash
find ~ -xdev ! -type l \( -perm -o+r -o -perm -g+r -o -perm -o+w \
     -o -perm -g+w -o -perm -o+x -o -perm -g+x \) -print0 2>/dev/null | xargs -0 -r chmod go-rwx
```

⭐ 重扫**不会**弄坏可执行文件：`go-rwx` 只动 group/other，owner 的 x 位原样保留
（实测 `sbatch_masked.sh` 变成 `-rwx------` 后照常能跑）。

## ⭐ 文件权限和作业隐藏是两件事，谁也替代不了谁

[[job-privacy-masking]] 那套（进程标题改成 compute-worker、SLURM 用哈希代号）解决的是
**`ps` 和 GPU 监控页上能看到什么** —— 那些信息由内核直接提供给同机器的所有人，
⛔ **和文件权限完全无关，家目录改成 `drwx------` 一点也挡不住它**。
反过来，进程标题改了也不影响别人能不能读你的结果文件。两套要各做各的。

⭐ 一个正好互补的例子：`~/jobs/.map.tsv` 是把哈希代号翻回真实作业名的映射表 ——
它要是像默认那样 644，任何人都能把代号还原成真名，整套隐藏就白做了。
现在它是 600，隐藏才真的成立。
