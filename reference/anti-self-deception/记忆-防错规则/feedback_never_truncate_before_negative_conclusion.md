**2026-08-22，同一天两次，方向相反。** 一次在检查输出后接 `head -2`，于是排在后面的检查项等于没跑；
一次在全库检索后接 `cut -c1-300`，⛔ **grep 确实命中了那一行，是截断把命中从输出里删掉了**——
那句话在第 600 个字符之后。**工具找到了，是操作的人剪掉的。**

⚠️ **横向那次更阴，成因是这个知识库的散文写法：一段就是一个物理行**，一行动辄上千字符，
砍到 300 就是砍掉一整段的大部分，⛔ **而输出看起来是一条完整的命中记录，没有任何迹象提示右边还有下文。**

⭐ **两次的后果都不是「少看了点东西」，是「据此下了一个否定结论」**：第一次判定某处退休写法已清干净，
第二次判定某句话在那个文件里不存在，⛔ **两次都写进了提交记录。**

**Why:** 确认一件事只要找到一处，⛔ **否定一件事要求证明一处都没有**——那是关于整个文件（或整批输出）的
全称断言，而全称断言是算术。⚠️ **截断把「我看了全部」偷换成「我看了前面一点」，而这个偷换在输出里不可见。**

**How to apply:**
- **读这个知识库的散文一律用 `fold -w`，不用 `cut -c`**——⭐ **折行是换行，截断是删除。**
- ⛔ **凡是要据以下否定结论的检索，输出一个字符都不许截断**（`cut` / `head` / `-m` 全禁），
  并在结论里写明**搜的是哪几种写法**。
- ⭐ 想控制输出量就**换更窄的搜索词**或**先数条数**（`| wc -l`），⛔ 不要靠砍输出。
- ⭐⭐ **假零的形态目录（2026-08-22 一天内实测到九种，⛔ 没有一种是想出来的，全是撞出来的）**：
  ①**排版连字**——`sufficient` 印成单个 `ﬃ` 码点，⚠️ 而一个 `ffi` 有**四种**排法（三字母 / `ﬃ` / `ﬀ`+`i` / `f`+`ﬁ`），实测那份期刊论文用的是最后一种；
  ②**断行连字符**——`confidence` 被排成 `confi-` 换行 `dence`；
  ③⭐ **多词短语跨行**——`monotonic relationship between` 零命中，而原文只是在两个词之间断了行。**这一种最阴，因为查询词本身没有任何特殊字符**；
  ④**同一符号的不同码点**——原文用数学减号（U+2212），搜的是普通连字符；
  ⑤**规范化折掉了语义**——把连字与变音符一起折的那一步，把脱离等号的组合斜线（否定号）折没了，`α≠β` 变成读得通的 `α=β`；
  ⑥**字体编码把数学换成数字**——某期刊 PDF 里 `(`→`4`、`,`→`1`，⛔ 而这个映射**不是一一对应的**，写替换表还原必然猜错；
  ⑦**扫描件没有文字层**——零命中只说明它读不出来；
  ⑧**喂进去的根本不是文本**——把 PDF 当文本读，得到八九万字符乱码，搜索安静返回零；
  ⑨**接口协议或参数写错**——同一个检索接口走加密连接返回结果、走普通连接返回零字节；过滤器语法写错则全部返回零。
  ⭐ **工具已落地**：`~/kb_tools/ligsearch.py` 覆盖 ①②③⑥⑦⑧（照普通拼写写查询词、直接吃 PDF、读不出来时报「本次搜索什么都没说明」而不是零）。
- ⛔⛔ **第十一种，是第十种在「核对别人的报告」这一侧的形态（2026-08-24）。**
  一个窗口的便条被检查报「时间字段是未来时间、超前 29 分钟」。⭐ **它去核，判定检查报错了**：
  字段写 01:20、当时 04:00，**对着墙上时钟年龄是正的**，所以不是未来时间。
  ⛔ **而那道检查比的根本不是墙上时钟，是文件的修改时间**——它写便条那一刻是 00:51，凭印象填了个整点 01:20，**超前正是 29 分钟**。
  ⭐⭐ **要害是：墙上时钟只测得出「旧」，测不出「编」。** ⚠️ 一个未来时间戳对着墙上时钟是**自洽**的，
  ⛔ **只有引入一个写它的人控制不了的量（文件修改时间）才现形。**
  ⭐ 而后果比原来那个错更贵：**它差点用一个测不到这件事的量，去否定一份测得到的报告。**
  **判据**：⛔ **核一份报告之前，先问「我用来核的这个量，测得到它说的那种故障吗？」**
  ⚠️ **测不到就等于没核，而且比没核更坏**——**因为你会带着一个「已经核过」的结论去推翻对的东西。**
  ⭐ 这与上面第十种同根：**第十种是对照与正式查询共用一条坏管子，这一种是核对方法与被核对象共用一个盲区。**

- ⛔⛔ **第十种，也是最狠的一种：对照实验和正式查询共用同一条坏管子（2026-08-23）。**
  查一篇论文有没有预印本，连查四次全零；⭐ **其中一次是特意做的对照查询——查一位已知发过几十篇预印本的作者——也是零。**
  ⚠️ 看上去像铁证，⛔ **而真因是那个接口现在从普通连接跳转到加密连接，`curl` 不带 `-L` 不跟跳转**，
  于是拿到一个**退出码 0、状态码 301、零字节**的响应，解析器在空文本里找不到条目，老实报「0 条」。
  ⭐ 我自己复现过：`code=301 bytes=0 exit=0`；加 `-L` 之后 `code=200 bytes=3304`。**每一环都工作正常，合起来是一句假话。**
  ⭐⭐ **最该记的不是那个域名，是那个对照为什么没救得了人**：对照与正式查询用了**同一条命令、同一个协议、同一个解析函数**，
  ⛔ **管子坏了两边一起坏**，⚠️ **于是对照的零反而让人更确信「确实没有」**——**一个失效的对照比没有对照更坏。**
  **做法**：①凡要据以下否定结论的网络请求，一律带 `-sL` 并打印 `%{http_code} %{size_download}`，
  ⛔ **先看字节数：0 字节＝本次查询没有结论**（与状态码无关，301/302 一样给 0 字节）；
  ②⭐ **对照查询必须走一条与正式查询不同的路**（换协议、换端点、或换一个完全不同的工具），
  **否则它验证的只是「这条管子对两个输入表现一致」，而那正是坏管子的表现。**

  ⛔ **它的自测里四例专测都是撞出来的**，源码注释写明了这一点——⚠️ **下一个人不许因为「看着冗余」而删掉其中任何一例。**
- ⛔⛔ **第十二种：本机的 `grep` 不是 GNU grep，它遇到含 NUL 字节的文件会整个跳过，一声不吭（2026-09-01 实测，一次污染了两批共二十余篇论文的检索结论）。**
  本机 `grep` 实为 **ugrep 7.8.4**，默认 `--binary-files=without-match`：⛔ **只要文件里有一个 NUL 字节，整个文件不搜，退出码 1，零输出，而且不打印 GNU grep 那句 `Binary file ... matches` 警告。**
  实测：`grep -c "policy" 2206.02346.txt` **什么都不打印、退出 1**；`grep -ac "policy"` 同一文件打印 **255**。⚠️ 连 `grep -ic "the"` 在只含一个 NUL 的文件上都返回空。
  ⭐ **NUL 从哪来**：从 PDF 抽文本时，数学大括号、`≥`、希腊字母这类字形解码失败就会落下 NUL。**当天 40 个抽取文本里 11 个中招**（NUL 数从 1 个到 1716 个不等），⛔ **而它们看起来完全正常，`head` 打印得好好的。**
  ⚠️ **危害的形状与本文件其它各种假零同型，但更广**：它不是某一个查询词失效，是**这个文件的所有查询一起失效**，于是一份「checkpoint 0 / deploy 0 / model selection 0 …」的漂亮零命中清单，实际上一次搜索都没发生。当天两篇论文的「零命中」结论被这样推翻——其中一篇真有 5 处 checkpoint、1 处 model selection，而那句 model selection 恰恰是要找的东西。
  ⭐⭐ **同伴窗口当日自查后补的两条，比上面那条判据更该记住。**
  ①**它这批 13 份抽取文本里 12 份含 NUL**（1 到 55 个不等），**包括它全部否定判定所依据的那几份**——它没出事的唯一原因是**它的检索几乎都写成 Python 的 `re.findall(open(f).read())`，Python 读 NUL 无碍**。⭐ **所以真正的修法不是「记得加 -a」，是「要下否定结论的检索一律用 Python 读文件，不走 shell 的 grep」**——前者靠人记得，后者靠工具本身就没有这个失效模式。⚠️ 它唯一一次用裸 grep 取上下文返回了零，当时归因为行边界问题、换 Python 就有了；事后看很可能同时踩了行边界与 NUL 两个坑，**只是换工具把两个一起掩掉了**——⛔ 这正是「换个工具就好了」为什么不能当成诊断。
  ②**它重跑时留下了一条反向证据，这个做法值得抄**：它不只确认「零命中还是零」，还特意找出一处**非零**的命中来证明搜索确实在工作（两篇讲高斯同伦与凸包络的论文里 `curricul` 各命中 1 次，不是 0，而且这一处推翻了它卡上原写的「这两篇完全不提课程」）。⭐ **一次全是零的复查，和一次根本没跑的复查，在输出上还是一样的；找到一个预期为真的命中才把两者分开。**

  **做法**：①**凡对 PDF 抽取文本下否定结论，先查 NUL**：`python3 -c "print(open(F,'rb').read().count(b'\x00'))"`，非零就先原地替换成空格（NUL 不携带信息）再搜；②**检索一律加 `-a`**（`grep -a`），代价为零；③⭐ **判据同第十种——「退出码 1 + 零输出」在这里不等于「没找到」，等于「没搜」**，两者在终端上不可区分，只能靠上面两条一律执行。
- ⛔ **第十三种：同一个 PDF，两个抽取器给出不同的文本（2026-09-01，同伴窗口实测）。**
  一篇 2009 年 ICML 论文里某张箱线图的纵轴标签（`best validation classification error`，与图注和正文说的 test error 互相矛盾——本身就是要抓的缺陷），**PyMuPDF 完全抽不到，`pdftotext -layout` 抽得到**。
  ⚠️ 于是「这篇没提某个词」这个结论会随**你选了哪个抽取器**而改变，而两边的输出都看不出缺了东西。
  **做法**：凡是要据以下否定结论的检索，**两个抽取器都跑**（`pypdf` / `PyMuPDF` 与 `pdftotext -layout` 至少各一），命中取并集；⭐ 尤其是**图注、坐标轴标签、表头**这类排版特殊的位置，它们恰恰是协议与矛盾最容易藏身的地方。
  ⭐⭐ **当日稍晚的第二个判例，比第一个严重，因为它不在图里：** 某篇论文**摘要与流程说明里的两整句散文**——「compute scalar statistics summarizing the policy's performance (without interacting with the environment)」与「existing hyperparameter selection methods for offline RL break the offline assumption by evaluating policies …」——在 `pypdf` 抽出的文本里**一个字都搜不到**，在 `pdftotext -layout` 抽出的同一篇里完整存在。
  ⚠️ **所以这条的适用范围不是「图注、坐标轴标签、表头」，是整篇**：连摘要里的普通句子都可能整句缺席，而缺席处读起来毫无异样。⛔ **凡要引一句「逐字原文」，先确认它在你手上这份抽取件里真的存在；搜不到时先换另一份抽取件，再考虑「这句话是编的」这个可能。**
- ⛔⛔ **第十四种不是新的失败方式，是对上面全部的重新分类（2026-09-01，两个窗口两天里四次撞同一堵墙之后合并出来的）。**
  两天里「库里没有这一页」这个结论被**四种互不相同的方式**做错：①`find … | head -5`——**检索被截断**；
  ②写下「本库没有、已请求」而两件事都没做——**检索根本没做**；③只探了书架、没查库——**同样是没做，只是自己以为做了**；
  ④路径里的撇号写成直的 `'` 而真实文件名是弯的 `’`，五个关键词全部零命中——**检索用错了字符**。
  ⭐⭐ **共同点只有一个：都在下「没有」这个否定结论，而支撑它的那次检索本身是坏的。失败方式各不相同，所以按失败方式设防必然漏**——防住了截断防不住撇号。
  ⛔ **只有按结论设防拦得住**：凡是要写「库里没有 / 架上没有 / 没人讲过 / 这篇不提」，**先问一句「支撑这句话的那次检索，会不会本身就是坏的」**，
  再从上面的形态目录里认领一种。⚠️ 具体到这个知识库，那一问最常见的三个答案是：**输出被 `head`/`cut` 截了**；
  **路径或查询词里的撇号、破折号跟文件里不是同一个字符**（`’` vs `'`、`—` vs `-`）；**根本没查库、只查了书架**。
  ⭐ 第 ② 种最值得单独记：它不留任何痕迹，**因为它没有产生过一次可疑的输出**——写下的那句「本库没有」读起来和查过之后写的完全一样。

- ⛔⛔ **第十五种：查询词与那本书里的叫法不是同一个词（2026-09-01，一天内两个窗口各撞一次）。**
  探书架问「社会选择那批概念库里有没有书」，`population consistency` 与 `independence of clones` 报**全书架零命中**，
  据此写了「书上没有这两个概念、只能登记不能补」。⛔ **字面没错，结论全错**：
  那本 Handbook of Computational Social Choice 里它们分别叫 **`reinforcement`**（书中自注「aka consistency」，
  有整整一节与形式定义）与 **`clone independence`**（正文有定义，还说明 ranked pairs 正是为达到它而提出的）。
  ⚠️ 同一天另一个窗口把 `graduated optimization` 判成全架零命中，
  而它的经典旧名 **`graduated non-convexity`** 就在架上一本里。
  ⭐⭐ **共同点：书用的是编者或原作者的术语，查的人用的是后来通行的术语。** 这与本文件其它假零同族，
  但成因不在工具也不在字符，**在于「这个概念只有一个名字」这个默认假设**。
  **做法（第二条是同伴窗口贡献的，比第一条好用，因为它给的是从哪里取候选叫法）**：
  ①凡 1980–90 年代就有的方法，报零命中前**必须再试一次它的旧名**；
  ②⭐ **顺手喂一次「书里那一章的章节标题词」**——章节标题一定是编者自己的叫法，
  拿它当查询词等于用这本书自己的术语再问一遍；
  ③⚠️ 判据同第十四种：**要下「书上没有这个概念」的结论，先问「我查的是这个概念，还是我习惯的那个名字」。**
  ⭐ 这一条实测有增量：照办之后，原判「书架覆盖十三个词里的十个」修正为**覆盖十二个**，
  真正缺的只剩一个（`agenda consistency`），而那一个有明确的论文出处可等。
  ⛔ **附一条写这条记录时当场踩的坑，同族**：往 memory 写这段时用了**未加引号的 heredoc**（`<<PY` 而非 `<<'PY'`），
  于是 Python 字符串里那些反引号被 shell 当成命令替换执行掉，
  **上面每一个用反引号括起来的术语都被替换成了空字符串**，写进文件的是一段少了七个关键词、读起来却完全通顺的话。
  ⚠️ 与本文件其它各条同型：**输出没有任何异常迹象**，`grep -c` 还报「已写入」。
  写 memory 或任何含反引号的内容一律用 `<<'EOF'`。

  ⭐ **两条的根都是「文本的形状不是工具假设的形状」**，一条造假命中，一条造假零。
