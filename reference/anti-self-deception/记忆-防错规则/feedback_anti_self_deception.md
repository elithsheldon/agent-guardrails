**Why**：无人值守/多轮循环里 LLM 的失败模式不是能力不足而是自欺——同族投票冒充陪审团、旧 PASS 引用到已改文件上、改措辞让 flag 消失冒充修复、失速后原地调参续跑。这些全是机制洞，堵法是机械件不是提示词。

## 协议

1. **停止门 A/B 分类学**：给任何自动循环设停止门时先问「无品味的笨脚本能答这个门吗？」能→Type-A（脚本自判，如 check_latex 退出码）；不能→Type-B（需独立/异视角裁决——异族模型最佳；至少换零上下文新 agent + 不同 lens，且**同模型 N 票只算一个带误差棒的意见**，不许当 N 独立票用）。复合门拆开：`score≥6 AND ready` 拆成 A 部分脚本判 + B 部分外判。现有对抗验证（book-read 双 agent、refute 投票）沿用，但报告措辞不许写「N 个独立审稿人一致」。
2. **audit_hash.py——LLM 审计判定绑输入哈希**：任何「验证过/审过=PASS」型判定若要跨会话被引用，record 时绑被验文件哈希：`python3 ~/.claude/scripts/audit_hash.py record --ledger <x.json> --audit <名> --verdict <PASS...> <files>`；引用旧判定前 `verify`——STALE=文件已改，旧 PASS 作废须重审。适用：vault 大波次收官判定、对抗验证 CONFIRMED、port-fidelity 审计。preflight 类每次全量重跑的检查不需要它。
3. **flag_ledger.py——flag 消失≠已修**：多轮人工核类 flag（P2 点检、审稿自查候选行、kb-audit flag）跨轮对账：每轮 `ingest`（stdin 每行 `rule<TAB>span`）；消失且未显式 `resolve --note`/`waive --reason` → UNRESOLVED_DISAPPEARANCE=FAIL；已了结再现→REOPENED。ID=归一化文本哈希，改空白大小写洗不掉。**2026-08-04 升级两件**（采自 ARIS forensics_gate 收据力学+paperjury unadjudicated 门，台账 [[paper-skill-survey]]，RED 五态验杀过）：`resolve --evidence <file>` 记 sha256 关单收据，此后每次 status 复 hash——**关单后改证据文件=STALE_EVIDENCE=判定作废重审**；`status --strict`=收官门——存在 OPEN 未判决的 flag 就 FAIL，**战役收官前必须跑 strict**（预算耗尽/循环卡死不能伪装完成）。配套约定：手工开 flag 时 span 里写明「什么样的编辑算修好」（close criterion），关卷对着这句核，防「改了但没改到点」。
4. **iteration_log.py——失速强制转向**：探索型循环（F 平台过夜收割、批量找 bug）每轮 `log --run <名> --new-findings <n>`；连 2 轮零净新→PIVOT=structural（换结构性约束，禁只调参续跑）、连 4 轮→PIVOT=human（发告警停跑）；`status` 退出码可供 cron。babysitter 只看死活，这个看失速，互补。
5. **done≠accepted（resume 语义）**：checkpoint/待办里「执行完成」与「验收通过」是两个状态；恢复会话续做时，从第一个**未验收**的阶段重做，不是第一个「没做完」的——自报 done 但没过对抗验证/停止门的阶段必须重验。写 SESSION CHECKPOINT 时显式标 done/accepted 二态。**第四桶+provenance（2026-08-05 采自 LongHorizon-Harness 收割件 3，用户拍板落地；台账 [[paper-skill-survey]]）**：状态台账（LEDGER/CHECKPOINT/EXPERIMENT_PLAN LIVE STATE）在 done/accepted/blocked 之外设第四态 **untrusted**（不可信/不可复用——产出存在但验收失败或验收器本身可疑，禁被下游引用）；每条「已完成」必须给 provenance（指向 verify 报告/gate 输出路径），给不出的降标「待审计」而非默认可信。
6. **判定异动先 diff 转录**：多轮审稿/验证分数突变时，先 diff 两轮的原始回答找翻转句，禁直接重掷骰子（重跑=拿到新意见，不是解释）。对抗验证类 agent 的关键结论落盘（tee 到 scratchpad 或台账），别随会话蒸发。
7. **主观打分锚定校准**（美感/质量类 rubric）：先给已知好/坏各 2-3 个锚样本打分，分不开=rubric 坏了先修 rubric；对目标打分必须点名「落后于哪个锚、哪条轴」。

8. **机械门 RED 纪律**（2026-08-03 加，old-coder 深潜触发的库内教训归拢，对抗验证 CONFIRMED；同类事故三连：07-10 `grep|sed` 恒真管道、07-28 KL 门报 CLEAN 靠用户肉眼抓、memory 软链 find 不跟随扫零文件）：**新建或修改**任何机械门（goal 谓词/check 脚本/stop-gate RULES 行）时双向验证——干净样本 PASS 之外必须喂已知坏样本**亲见它 FAIL**；从没见过 FAIL 的门可能是真空门。改动较大时种 3-5 个形状各异的缺陷样本逐个验杀（脚本化持久化进 selftest，别手改手还原）。环境漂移型 fail-open（软链/glob 落空）用更便宜的机械件：**门自证输入非空——被扫文件计数进判定，计数 0=FAIL**。单边不变量配反向对照。触发点只在创建/修改时，静态未动的门不周期性折腾。**共享检查器改动的全依赖回归（2026-08-05 Compost 提案一，用户签字；事故=08-04 preflight §12 只在 ICLR 仓验干净面，当晚三仓 goal 齐红、其中一仓是门配置错）**：改**被多条 goal 共享**的检查脚本时，当场枚举全部依赖它的 goal 逐条重跑，每个红**分类**——门自身 bug（如输入自证 FAIL 的仓形态没考虑）＝改门者当场修；产品真债务＝**不许顺手修**，记 known-red＋写进仓主队列（见规则 15 归属）。做不到全绿就显式记「known-red＋原因」，不许留着让日巡替你发现。**两个补充坏样本类（2026-08-05 采自 <collaborator> argdown_lint/grade_judge 实录，台账 [[workflow-skill-survey]]）**：①exit 码语义混淆——编码崩溃（emoji 撞 cp950 控制台）的 exit 1 与「gate 触发」的 exit 1 不可区分，建门时输出流先 `reconfigure(encoding="utf-8")` 且异常路径给独立 exit 码；②**模型自报判决与脚本重算不符时，重算值是权威、分歧本身是「重查某个分项评分」的信号**——不给模型覆写权，也不静默采纳脚本值完事（分歧=可能有分项打错了）。

9. **强共识反查**（2026-08-04 采自 paperjury recall Mode B，台账 [[paper-skill-survey]]；把规则 1 的「同模型 N 票打折」升级为主动对冲）：对抗验证多 agent 意见**高度一致**的指控/判定簇，动笔修复前追加一个 fresh skeptic 专问一件事——「这个一致会不会是相关性错误（correlated-wrong consensus）？」；raiser 置信度低的强共识加重查。越一致越要抽查，不是越一致越放心。
10. **verifier 指控绑逐字引文**（同上出处 evidence_anchor + 机械 quote-verify）：对抗验证/审计 agent 报 FIXED/FLAG 类指控时必须附「所依原文的逐字引文」，签收侧 grep 核该引文真在源文件里——引不出=没读，整条作废。与 audit_hash 互补：那个绑**输入**，这个绑**指控本身**；直接打击同模型 verifier 的幻觉指控。
11. **修复溯源+空转熔断**（同上出处 SNL red_team/loop_mode 两小件）：多轮审计循环里每个 fix 记它对应的规则 ID（fix 可追溯到具体哪条规则，"Audited" 无 grep 输出=INVALID）；**连续 2 轮同一批 findings 原样存活→停止循环并上报 blocker**，不许空转（与 iteration_log 的「零净新」失速互补：那管没新发现，这管旧发现修不动）。
12. **门/审计 agent 的验收也走 RED**（同上出处 paperjury seeded-defect+bait 设计；规则 8 的推广）：验收一个 reviewer/verifier agent 或复合审计管线时，不只喂干净样本——**种入已知缺陷（含"看似缺陷实则可辩护"的诱饵）**，要求缺陷全检出且诱饵零误报；假阳性对照和假阴性检出同等重要。
13. **verify 波三不变式**（2026-08-05 采自 LongHorizon-Harness 收割件 1+2，用户拍板落地；挂 wave driver / 对抗验证签收，与 [[herdr-agent-driver]] 的「verify 必在 commit 前」互补）：① **审计者动了树=判决作废**——verify/audit agent 收尾时跑 `git status --porcelain`，非空即该 agent 的 verdict 无效（审计和修复必须是两个角色；FIXED 类流程里修复完要重新起 verify）；② **verdict 两行控制头**——verify 产出首两行固定 `VERDICT: PASS|FIXED|FLAG` + `CONFIDENCE: high|med|low`，签收脚本只解析控制头；**控制头缺失/畸形→强制按最保守档（FLAG）处理**，不许解析器从散文里猜判决；③ 允许 verify agent 做 ≤3 轮**无工具微修复**（笔误级），但微修复期间动了树→回到①判决作废。
14. **删除对账**（同上出处收割件 4；bash_safety_guard 已配套记账 ts+cwd）：「声称删了/清了」≠「删了」——收尾报告里的删除类声明必须配 `git status`/`ls` 对账证据；guard 的 `~/.claude/safety_guard.log` 是拦截/放行的 append-only 台账，事后追责用它对时间线。

15. **红 goal 处理先判仓归属（2026-08-05 Compost 提案一附带，用户签字；封「VIOLATIONS 广播到每个新会话→多窗口同修一仓」的敞口）**：goals hook 广播的是「有事」不是「都来干」。动手修红 goal 的产物前先判目标仓归属——**由活跃会话持有的仓**（tmux driver 窗口在跑、或 LIVE STATE/memory 标了 owner 的），本会话只许把债务记进对方队列（TODO/LIVE STATE/memory checkpoint），不许直接动产物；`~/.claude/scripts` 等基建仓归改动发起者。判例（正面）：08-04 caption 门报 ICLR 稿 6 条债，本会话只记 TODO，主会话次日自清——修复权单点，零撞车。

16. **检查器打印的「结论句」不是结论（2026-08-15 事故，用户抓）**：`scan_bare_refs.py` 当时无论多少命中都硬编码打印 `-- N hit(s); 0 required after triage`——那个 **0 是写死的常量，不是算出来的**，而句子读起来像是「已分诊完毕、无需处理」。我据此放行了 19 条命中；事后逐条查，**15 条其实该改写**（多数只是「在哪里」的定位，用内容描述完全能代替），1 条还是把「Q 表 360 项」误咬成「表 3」的假阳性，真正够格放行的只有 4 条。**这不是工具骗了我——脚本自己的 docstring 明写着「命中 ≠ 必改」「退出码 1=有命中待人工分诊」，退出码也确实是 1；只有那句打印跟它自己的文档矛盾，而我信了打印没信文档。** 三条纪律：①**凡是规则把裁量权明写给人的检查，工具的汇总行一律不作判决**——退出码非零就是「你还没做完」，不管它印了什么；②**建/改检查器时，别让它打印任何自己没算过的判断词**（「required」「need」「ok」「no action」），要么给真算出来的数，要么只报事实计数（该脚本当日已改成「待人工分诊 —— 这不是判决，本脚本不做分诊」）；③**读到听起来像结论的一行时，先去看它是不是常量**——一个 grep 就够。同族先例：规则 8 的「恒真管道」「报 CLEAN 靠肉眼抓」，区别是那些门算错了，这个门算对了却把话说错了。
16b. **⛔ 别把检查脚本放进管道再问退出码——那问的是管道最后一个命令（2026-08-15，另一会话踩到并共享，本会话复现且自查）**：写成 `python3 check_x.py 2>&1 | tail -6; echo "EXIT=$?"`，屏幕会打出 `EXIT=0` 而**那是 `tail` 的退出码**；脚本自己可能正报着红。当天判例：某会话据此把一个真实退出码为 1 的队列检查当成通过（两条真实的记账冲突），几乎带着红提交。
    **正确写法**（先重定向、立刻取 `$?`、再看内容）：
    ```
    python3 <脚本> > /tmp/out.txt 2>&1; echo "EXIT=$?"; tail -3 /tmp/out.txt
    ```
    也可以 `set -o pipefail`，但最稳的是别把要判退出码的命令放进管道。
    **这条与规则 16 是**同一家族的两个不同根因**：16 是**脚本骗你**（它打印了自己没算过的判断词）；这一条是**你问错了对象**（脚本没骗人，是你没在问它）。后者更隐蔽，因为屏幕上那个 `EXIT=0` 是真的、只不过属于别人。**自查方式**：回看自己这一轮跑过的检查，凡是形如 `<脚本> | head/tail/grep …; echo $?` 的，一律用上面的写法重跑一遍——本会话当天自查了六个检查，重跑后结论未变（幸），但写法本身已属侥幸。

16c. **⛔ 用来下结论的命令，输出一律不许截断（2026-08-15，同伴纠正我的误判；与 16、16b 同族的第三个变体）**：我为了证伪同伴的一条报告，跑了 `git show --stat <提交> | head -8`，看到七个文件、没有那个共享记录文件，于是判定「那次提交不含它」并回复说他的实例不成立。**同伴复核后我错了**：那次提交实际有 **9 个文件**，那个记录文件排在**倒数第二**，正好落在被 `head -8` 切掉的两行里。它另给了一条独立证据——按内容溯源查那段文字第一次进版本库是哪一次提交，返回的正是那一次。
    **三个变体的共同点是「屏幕上那句话是真的，但它不是你要的答案」**：16 是**脚本骗你**（打印了自己没算过的判断词）；16b 是**问错了对象**（管道里的退出码属于管道最后一个命令）；这一条是**只看了对象的一部分**（列表是真的，只是不完整，而**不完整与「没有」长得一模一样**）。
    **规则**：`head` / `tail` / `grep` 这类截断只许用于**浏览**，⛔ **不许用于下结论**。要判定就完整输出（必要时 `| cat` 防分页），或者换成能直接回答问题的命令——本例中 `git log -S "<那段文字>" -- <文件>` 一步就给出了不受截断影响的答案。**尤其危险的是我当时在用它「证伪别人」**：截断造成的假象恰好支持了我想说的结论，而我没有再问一句「会不会是我没看全」。
    附带教训：**我据此回复对方「你的实例不成立」，是把自己的观测误差说成了对方的记述错误**。今天已因此产生一次错误的更正。**推翻别人的报告，比接受它需要更高的证据标准**，因为对方通常在现场、你通常不在。

17. **流程清单不许自称「全部」（同一事故的第二个根因）**：`/paper-read` 的机械门表当时写着「下表是**全部**的门，没有第二处清单」，而真正 binding 的常驻停止门在 `~/.claude/goals/*.md`，**可以在不改那张表的情况下新增**——于是表悄悄落后，照表跑全的人以为自己跑全了。同类漂移当天查出两处：`bare-refs-papers-md` 与 `card-length` 的常驻门都是**增量版**（比对 baseline），而清单里列的是普通版，跑普通版过了不等于常驻门过了。**规则**：任何流程清单只许自称「本流程自己的门」；收尾时**按本批写过的目录**去 `~/.claude/goals/` 找盯着它的常驻门（`grep -m1 '^predicate:' ~/.claude/goals/<名>.md` 取照抄命令）。写清单时禁用「全部/唯一/没有第二处」这类完备性断言，除非那份清单是机器从单源生成的。

18. **⛔ 往子任务的指令里写房规，一律从房规文件复制原文，不许凭记忆转述（2026-08-15 事故）**：给两个起草 agent 写任务说明时，我凭记忆写了两条关于 tikzjax 的规矩，**两条都错**，而房规原文（vault `_meta/CONVENTIONS.md` 的 Diagrams 节）就在手边、写得毫不含糊。①我写「必须带完整的 `\documentclass` 骨架」——原文写的骨架是 **`\usepackage{...}` → `\begin{document}` → `\begin{tikzpicture}` → `\end{document}`，压根没有 `\documentclass`**（全库 1125 个 tikz 块无一例外，实测 0 个带它）。②我写「不预载任何数学宏包（no amsmath, no amssymb）」——原文是「基础格式不预载数学宏包」，**紧接着的后半句是「`\usepackage{amsmath}` 之后就能用」并附了可用包清单**，我把决定性的那半句丢了。
    **两条错误的代价是不对称的，这才是要记的部分**：第一条当场被 `check_tikz.sh` 拦下（渲染直接失败，报「出现两个 documentclass」），改一行就好——**有机械检查盯着的错误是廉价的**。第二条**没有任何检查能看见**：起草 agent 把「不能用数学宏包」理解成整张卡都别写公式，于是两张卡的**正文一个 `$` 都没有**，其中一张的推导附录把十二步数学推导整个用英文散文写出来（「the term at k equals the term at k-1 divided by one minus the increasing probability, minus …」），语法合法、长度合规、所有检查全绿，只有人读了才知道不对。
    **规则**：给 subagent 写指令时，凡涉及房规的段落，**打开房规文件把相关条目原样粘进去**（贵不了几个 token），或者直接给文件路径让它自己读；禁止「我记得房规是说……」。判别信号：只要你写的规矩里出现「必须/一律/绝不」而你没在这一轮打开过那份文件，就是在凭记忆立法。同族=规则 16「读到听起来像结论的一行先看它是不是常量」，都是**把二手转述当一手事实**；区别在于 16 的二手来源是脚本的打印，这条的二手来源是我自己的记忆。

26. **⛔ 平行推导也是一种重复：动笔引某页之前，先看那页自己链了什么（2026-08-15，概念窗口实例）**：它在一页里写了一段「自己的解读」——用序结构代替度量、把某个经典不动点定理看成另一个定理在唯一性成立时的特例。**动笔去链邻页之前它先 grep 了那页链着谁，发现库里早就有那两个定理各自的页，而且那段解读已经被独立写过一遍、措辞几乎一样。** 于是它把自己那节改成直接引定理，只留一个新实例。

    **为什么这属于防自欺**：平行推导不会触发任何检查（两页都合法、内容都对），但它让同一件事在库里有了两个真相源，日后改一处漏一处。**它和「判定只活在消息里、迟早被重新犯一遍」是同一个毛病的两种形态**：前者重复的是推理，后者重复的是错误。

27. **⛔ 症状出现在哪一层，和原因在哪一层，是两件事——我为此把一条错判写进了房规（2026-08-15，同伴查出根因后推翻我）**：同伴报「上标里的希腊字母渲成了另一个字母」，我做最小例子、读渲染产物用到的字体，看到**上标走 7 号字体、正常字号走 10 号**，于是判定「两套字体的字符映射不同」，写进房规与本文件，判据是「图里凡有上下标里的希腊字母，一律回渲染产物核字符」。
    **那条是错的。** 同伴后来问了一个我没问的问题——**「为什么正常字号是对的？」**——并读了渲染产物里的**码位**：正常字号与上标里**是同一个码位 `0xb5`**，只是字体名一个是 10 号一个是 7 号。同一码位两种结果，**就不可能是排版那一端出的错**。查本机字体：只有 10 号的两个，**所有小号字体一个都没有**。所以正常字号取到真字体、走 Computer Modern 自己的编码，那个码位就是 θ；上下标取不到、退回系统字体，同一码位就成了另一个字符。**拉丁字母「字符对但字形不对」也是同一个原因**——ASCII 码位在退回去的字体里还是同一个字母。**两个症状一个根因，而我把「上标里」当成了原因，它其实只是「小号字体缺失」的一个可见后果。**
    ⛔ **那条错判的实际代价**：它指导人去**改正确的源文件**——同伴为躲这个假症状，把一张图里的指数改写过一次；库里 240 个文件、789 处上下标希腊字母，按那条判据全都成了「待核」，而**它们一直是对的**（Obsidian 自带完整字体，另一端一直渲得对）。
    **三条纪律**：①**看到「某个位置的东西不对」时，先问「同类的东西在别的位置为什么是对的」**——这个反问一条命令就能问出答案，而它区分的正是症状层与原因层；②**判定字符渲染错，必须读到码位**，只看字体名不够（字体名只说明取了哪个文件，码位才说明取的是哪个字符）；③**环境缺失造成的假症状，修环境不修产物**——本例的修法是把渲染引擎自带的整套字体装给系统栅格化器，磁盘上本来就有。
    附带一条仍然成立的：**tikz 里用 `\mathbb` 必须先 `\usepackage{amssymb}`，漏了是硬崩不是警告**（渲染检查只报「TeX 引擎渲染失败」，一行诊断都没有）。

28. **⛔ 要拿来判断成败的命令，绝不接管道（2026-08-15，一天内三个窗口各栽一次）**：我跑图形渲染检查时写了 `bash check_tikz.sh <清单> 2>&1 | tail -3`，看到它打印 `FONT GATE FAIL` 却返回 0，于是**报告「这个检查会绿着放行」**。同伴复现后指出：`$?` 取的是管道最后一个命令的退出码。我用同一份输入两跑对照确认——**裸跑 exit=1，接 `tail -3` exit=0，输出文字一模一样**。同一天另两例：读论文窗口把队列检查接进管道得到假通过；<collaborator> 用 `head -8` 截断输出去证伪同伴的报告，结论完全反了。
    **规则**：**截断与管道（`| tail`、`| head`、`| grep`）只许用来浏览输出；任何要据以宣布通过/失败的运行，一律裸跑，或重定向到文件再读那个文件。**
    **下次什么时候会用到**：跑任何机械检查、任何测试、任何 `git`/构建命令并打算根据结果决定下一步时。⚠️ 尤其是输出很长、你本能想截断的时候——**那正是最该不截断的时候**。
    **⚠️ 2026-08-18 又一次，形状值得单记**：验一个自检脚本时把它接进管道再问退出码，**问到的是管道最后一个命令的退出码，不是脚本的**。于是屏幕上「有失败」配着退出码 0——⭐ **这是一个「看起来自洽的错误结论」**：两个信号互相矛盾，人的第一反应是去怀疑**被测的东西**（「这脚本失败了怎么还返回 0？」），而不是怀疑**自己的量法**。正确做法是先重定向到文件、再单独取退出码。

    ⛔ **2026-09-01 第四次，同一个人同一天**：跑「产物里有没有用原论文编号指代」那道增量检查时写成 `bash check_bare_refs_delta.sh ... | tail -6; echo $?`，屏幕上有命中、退出码显示 0，我差点当它通过。裸跑才看到真实退出码是 1。⭐ **三条旧记录没能拦住第四次，说明「记得这件事」不够用**——真正管用的是把它变成写命令时的手型：**凡是 `bash <某个检查>` 或 `python3 <某个检查>`，一律先重定向到文件再 `echo $?`，要看输出就之后 `tail` 那个文件**，不在同一行接管道。

29. **⛔ 判定「对方/某物坏了」之前，先跑一个同时的对照，测一测观测手段本身（2026-08-15，三个窗口同一天各栽一次，我栽两次）**：我两次给某窗口发消息返回失败，就把它当成「那个窗口没反应」的旁证交给同伴，还让对方可以附进给用户的邮件。同伴那边的依据是终端画面里找不到发过去的字——**而那个画面停在旧的一帧不刷新**；权威证据（对方自己的会话记录）显示消息一条不少全都到了。第三个窗口量到零 CPU、零读写、画面校验和不变，也据此断言停摆并请用户裁定——**对方其实活着，随后一次性提交了四篇**。
    **为什么会发生**：这三条依据测的都不是「对方死没死」，而是「我这条观测链通不通」。它们被当成三个独立测量拼成「都指向同一结论」，于是**证据不足被包装成了证据充分**。
    **规则**：报「某某挂了 / 没反应 / 丢了」之前，**用同样的手段去测一个确定活着的对象，且对照必须与被质疑的那次尽量同时**。对照也失败＝手段坏了；对照成功也只能说明手段当时是好的。我事后补做的对照更进一步：**几十分钟后同一个名字就通了**，说明那两次失败是一时的，信息量接近零。
    **下次什么时候会用到**：任何要写进汇报或邮件的「X 不工作了」；以及任何时候你想说「多个证据都指向同一结论」——先逐条问**这一条测的是不是正是那件事**。

30. **⭐ 怀疑权威源写错了，就算一个最小实例，不要讲道理（2026-08-15，一天两次，两次都成立）**：其一，库里一张统计卡把 Cheeger 不等式写成夹住「第二大特征值的**模**」。我没有停在「这看着不对」，而是构造两态链 $K(1,1)=K(2,2)=\varepsilon$（满足该卡自己写的不可约+非周期前提）实算：$\varepsilon=0.05$ 时几何量 $h=0.95$、模 $=0.90$，而声称的上界只有 $0.549$。其二，Handbook 第 27 章把 parity 定义成「最小优先级为偶」，却引了一个只在「最大优先级为偶」下成立的归约；两状态环、$n=2$、优先级 $0/1$，报酬 $+1$ 与 $-2$，长期平均 $-\tfrac12$，两个获胜集当场分道扬镳。
    **额外一步同样重要**：第一例我随后**把原书那一页渲成图像读了原文**，确认书上前后一个附加条件都没有——于是诊断从「卡抄错了」变成「**漏条件的是书**」，而这两种诊断指向**完全不同的修法**（去改的人不要在那页上找抄写错误，那里没有）。
    **下次什么时候会用到**：照书写页时觉得某个结论「怪怪的」；以及**给别人报错误之前**——一个能算的反例把「我觉得」变成「我算过」，而回源核对把「谁写错了」从猜变成查。

31. **⛔ 只能靠做那件被明令禁止的事才能消掉的红灯，比没有红灯更危险（2026-08-15）**：产物对账那个检查每天都要报一次「这张卡已提交、但待读清单里那一行还没勾」。而这**正是流程要求的状态**——读论文的规矩把「翻勾」排在最后，理由是那一行就是断点记录，先翻勾再写会让被打断的批次留下一行谎报已读的记录、那篇论文从此没人再碰。检查的说明里甚至已经写明「这不是缺陷、⛔ 绝不许提前翻勾去消红」，**但它照旧以失败退出**，于是每天的例行检查都把它当作待修违规推给当班的人。
    **为什么危险**：它把唯一能关掉红灯的动作，设成了流程明令禁止的那个动作。人不会永远忍着——要么去做那件被禁的事（正好造出这条顺序要防的事故），要么学会无视这一项红灯（于是这一项从此再也拦不住任何真缺陷）。**两条出路都比没有这个检查更坏。**
    **修法的形状**：给"流程要求的中间态"一个**按时间自动消失**的通道，而不是给它一个豁免。本例按**入库时间**分流（4 小时内提交的单列出来不算缺陷，超时仍报），并且取的是最后一次提交时间**不是文件修改时间**——`git pull` 会刷新后者，用它会把别人拉下来的东西算成自己刚写的。
    **下次什么时候会用到**：任何时候你发现某个检查"天天报同一条、大家都知道不用管"。**那不是噪声，那是设计缺陷**：先问"消掉它的正当动作是什么"，如果答案是"没有正当动作"或者"那个动作是被禁的"，要改的是检查不是人。

32. **⛔ 由被检查者自己填、检查又拿它当依据的字段，必须有一个独立来源来对照（2026-08-15，一天四例）**：交接便条里有个"最后更新时刻"字段，而"这份便条过期没有"这个判定读的**就是这个字段**。有窗口把它写成未来时间——于是"多久没更新"算出来是负数、永远小于阈值，**那份便条从此永久显示新鲜**。
    **这一类错的特征**：它不是让检查报错，是让检查**永远不报错**。所以它不会被任何"看红灯有没有亮"的巡视发现——它恰恰表现为一切正常。
    **修法**：拿一个**被检查者填不了的量**去对照。本例用文件的修改时间：字段比它新 5 分钟以上＝时间是编的；旧 90 分钟以上＝改了内容忘了改字段。装上当场抓到一个正在发生的实例。
    **当事窗口自报的实例与成因（k-papers，合并自它自己写的同题条目）**：它写的是 22:05，实际时刻是 20:37，**超前 88 分钟**。成因不是手滑——**第一次填那个字段时它是用命令取的，后两次更新便条时凭印象估**。所以那句话值得原样记住：**一个字段只要有一次可以凭印象填，它就迟早会被凭印象填**；配套动作是"写时间戳一律用命令取"（`NOW=$(TZ=Asia/Tokyo date '+%Y-%m-%dT%H:%M+09:00')`），不是"下次注意"。
    **它还多给了一条判据，值得单列**：⚠️ **看到一个检查长期不报红，先问它有没有可能已经被写坏成了永不报红**，而不是当作情况良好。这一类错的共同形状是**失败方向朝着「一切正常」**，所以没有任何人会主动来告诉你。
    **下次什么时候会用到**：设计任何自报字段（状态=在写/已完成、进度百分比、最后更新时刻、"我已核对过"标记）时；以及看到某个自报字段长期正常时——**先问"它写错了会怎样"，如果答案是"没人会知道"，就得配对照**。
    ⭐⭐ **2026-08-27 补第二问：不可伪造的量，未必是你要问的那个量。**
    本条到这里为止只说了一句「拿一个被检查者填不了的量去对照」。⛔ **只问这一句，会挑出一个又硬又答非所问的量。** 同一天出了两个判例：
    · 一道检查要问「读论文那个窗口有没有在别人的地盘上建文件」，取的量是「知识库里所有未跟踪的文件」——`git status` 谁也编不了，**但它回答的不是「谁建的」**；于是每晚写日志的定时作业一落盘，它就指着那些文件说某个窗口越界。⚠️ 那个脚本自己的注释里还写着「后者是我改不动的量」，**「我改不动」被当成了「它答得对」**。
    · 另一道报「改了内容没改字段」，量是文件修改时间与字段值之差——同样不可伪造，**而且这次量本身完全正确**；错在那句话**预设了改动出自便条的主人**。真因是另一个窗口直接往那份便条里追加了一整节。⭐ 量测对了，它被说成回答的那个问题错了。
    **所以判据是两问，两问都过才算数**：① 证据来自被检查方控制不了的量吗；② **这个量回答的是我要问的那个问题吗**。⚠️ 第二问更容易漏，因为第一问答「是」的那种踏实感正好把第二问关掉。
    **说不清的时候怎么办**：判例一里「谁建的」文件系统根本给不出。⛔ 这时让检查**把这份不确定说出来**，别猜一个作者；相应地，写的人那一侧要主动留证据（往别人的便条里追加内容时署名）。**证据只能由写的人留下，检查造不出来。**
    ⭐ **判例全文与更多细节在知识库那份记忆里**（不在共享这一份，从主目录搜不到——用 `memgrep`）：`~/.claude/projects/-home-mil-n-chang-ObsidianVault/memory/``feedback-checks-need-evidence-the-subject-cannot-set.md` 末节。⚠️ 它记在那边是因为发现者在那边工作；**但这条规矩是跨项目的**，所以这里保留可独立执行的两问，不只放指针 —— 一条看不见的规矩对看不见它的窗口不生效。

33. **⛔ 被超时杀掉的运行不是一次有效运行，它的退出码不是那个命令的结论（2026-08-15）**：我用 `timeout 300` 跑一个约 25 分钟的全库检查，拿到退出码后据此下了结论；**那个退出码是 124，意思是"被杀了"**，不是那个检查的判决。我当时还把这个结论用来纠正同伴。
    **为什么会发生**：退出码只有一个数字，而"没跑完"和"跑完了、结论是失败"在这个数字上长得不一样却同样刺眼——`124` 和 `1` 都不是 0，扫一眼都像"失败"。
    **规则**：**读退出码之前先确认这次运行是自己结束的**。`124` 一律当"没有结果"处理，不当"失败"；给长任务设超时的时候，超时值要按实测耗时定，定不准就放后台跑完再看。
    **下次什么时候会用到**：任何给命令加 `timeout` 的场合，尤其是全库扫描、长测试、网络请求。

34. **⭐ "信人还是信机器"是错的问法，正确的问法是"谁在测的正是那件事"（2026-08-15，同一天两个方向的证据）**：这一天里多数教训是**人的判断压过机械误报**（几何检查全库 62 处零真阳性、拿页名当检索词造成的假阴性、产物对账把流程中间态当缺陷）。但**同一天有两次方向相反**：测量图上文字与线条间距的那项检查，两次抓到"亲眼看过渲染图并已放行"的真缺陷——一次是某个集合自己的椭圆边线从标签开头两个字母上穿过，一次是箭头从单词字母中间穿过，在整页尺寸下肉眼确实看不见。
    **判据**：算得出坐标与像素的，机械胜；判断"这个词在这句话里指的是不是那个对象"的，人胜。
    **为什么必须两半一起记**：只记前一半，就会养成"机械检查不可信"的通则，然后在后一半上栽；只记后一半，就会把误报当任务单去做。**今天的四类同名不同物里，最难防的一例（一个组合目标看着像另一个目标的特例、其实是并列的两类）是靠读承载链接的那句话抓到的，任何脚本都抓不到**——而同一天肉眼放行的两处图缺陷，任何人再看一遍也看不出来。

35. **⭐ 独立复核里，「重读一遍」永远确认你已经相信的东西；换成「算一遍」才可能推翻它（2026-08-15，k-books 窗口写极大单调那页时实测）**：页面把一条复合梯度的最小范数速度写成了本库通用的度量投影，而书上那个投影是在**另一个范数**下取的（由耦合算子的转置诱导）。这处**读多少遍都读不出来**——两种写法在纸面上都成立，差别只在一个下标。复核方没有再读，而是构造了一个二维实例（对角耦合、两个分量不等）把两边都算出来：**真值 0.4472，页面读法 0.5590，差 25%**。
    ⭐ **同一次里更值钱的是它顺手做的第二件事**：它接着核了下游那个多智能体的例子**不需要改**——那里的转置结构恰好让两个范数成比例、投影重合。**如果按第一处的发现一刀切替换，会把一段本来正确的内容改错。** 也就是说，找到一个错误之后，**「这个错误的影响范围到哪里」和「这个错误是不是真的」一样需要被算出来**，不能顺推。
    **为什么会发生**：重读用的是与写作时相同的理解，所以它检验的是「我有没有照我以为的意思写下来」，而不是「我以为的意思对不对」。算一遍才引入一个独立于理解的判据。
    **下次什么时候会用到**：复核任何**两种写法在纸面上都合理**的地方——投影在哪个范数下取、锥的方向与内外、常数的归一化、下标是行还是列。**判据**：如果你发现自己在用「这样讲得通」来支持一个判断，那就是该算最小实例的信号（与第 30 条同族：那一条是怀疑书，这一条是怀疑自己写的页）。

36. **⭐ 全库跑的检查报红时，先做两步归属判定，再决定动不动手（2026-08-15，一个下午三次，每次被拦的都不是自己的债）**：多个会话共写同一个工作副本，而那些检查是全库跑、不分窗口的，**于是谁先收尾，谁就把别人半写完的产物当成自己的欠债**，而且**修不了**——产物是别人的，对方还在写。
    **两步判定，缺一步会错**：① 看文件状态（`git status --porcelain <那一页>`）——未跟踪或已改未提交，多半是别人正在写；② **再看改动内容**（`git diff`）是不是自己的题材。⚠️ **只看状态不够**：同一个文件夹可能是两条工作线的交界，当天就有两个窗口据此把对方的产物认成自己的；而只看类别也不够，因为同一类文件里会混着自己刚写完还没提交的东西。
    **判成别人的，就只登记给对方、不动手**（对方多半会把新页与目录条目放在同一次提交里，插手会撞车）。
    ⚠️ **别把「报红」当噪音去压制**：同伴指出的一个真实反面——「等对方静默一段时间再报」这种折中会把**「他还在写」**和**「他写完就走了、忘了收尾」**合并成同一个观测，而后者恰恰是最该被抓住的。当天的正确修法是**改范围不改判据**（那项检查经用户裁定改成只看已进版本库的文件，未提交的照常打印但不计入失败，一提交就进入范围）。⛔ 为了消红而提前登记或提前提交是作假，会造出「地图说有这一页、库里没有」的假账。
    **下次什么时候会用到**：任何全库/全仓检查在多会话环境下报红时；以及任何时候想「把一个吵的检查调安静一点」——先问**它吵的是不是正是它该抓的那件事**。

37. **⛔ 工作副本是绿的，不等于版本库是绿的（2026-08-15 真实事故，四个窗口同时看不见）**：另一个窗口提交那份共享的阅读顺序文件时，把我刚写进去、指向一张**还没提交**的笔记页的那一行一起带走了。于是版本库里挂着一条指不到的链接，而**四个窗口各自跑链接检查全部 CLEAN**——因为检查遍历的是各自的工作副本，那张页面就在磁盘上躺着。
    **为什么会发生**：所有现成检查读的都是「我看得见的树」，而别人克隆到的是「提交出来的那份树」，这两者在多窗口共享工作副本上**经常不同**，且差异永远朝着「本地更完整」的方向。所以这一类缺陷的自然状态就是**全员绿灯**。
    **办法（唯一测得出来的）**：把当前提交导出到临时目录，在那份纯净快照上跑检查——
    `T=$(mktemp -d); git archive HEAD | tar -x -C "$T"; python3 "$T/_meta/scripts/check_links.py" | grep -E "Dangling|RESULT"; rm -rf "$T"`
    当天实测工作副本 `CLEAN`、纯快照 `Dangling wikilinks: 1`，**两个结果同时为真**。
    **配套的工序修法（不需要任何工具）**：**先提交页面、再写地图行**。被打断时留下「有页面找不到入口」，而不是「有入口指向不存在的页面」——前者只是不好找，后者是断链。
    **下次什么时候会用到**：任何一次 push 之前，只要本次涉及**共享的索引/地图/目录文件**；以及任何时候想根据机械检查的绿色宣布「库里是干净的」。⚠️ 还有一条推论：**`git commit <共享文件>` 提交的是那个文件的全部内容**，不存在只提交自己那几行的做法（`git add -p` 在本环境不可用），所以按下提交的人替当时写在里面的所有人做了决定，**而他看不见别人的页面有没有进库**。

38. **⛔ 写错的退路比没有退路更糟，所以退路必须带自检（2026-08-15，栽在我自己写的便条上）**：我在交接便条里写死了「会话间消息发不出去时，退路是往对方终端打字」。当天对另一个窗口**两条通道同时失效**：消息返回失败，而 send-keys 打进去的字**根本不出现在输入框里**，连单发一个 `test` 都不显示——**而所有表面诊断读数全部正常**（进程活着、前台程序就是它、不在翻页模式）。
    **为什么会发生**：我把「这条路在一个窗口上通过」写成了「这条路通」。**一条无条件的退路会让接手的人绕开真正该做的诊断**，因为它读起来像结论。
    **规则**：写进便条的每条退路都要带一步**当场可验的自检**，并写明自检失败时怎么办。这一条的自检是：打完字**先 `capture-pane` 看字有没有真的出现在输入框里，出现了才单独发 `Enter`**；没出现就是这条也不通，⛔ 别再发 `Enter`（对一个不接收输入的窗口连发回车，唯一的作用是让人以为送到了）。
    **两条都不通时**：这属于**联系不上**，不属于「对方不理我」——把话写进对方能读到的落盘位置，只是登记别人的债就到此为止继续干活，卡住自己的产出才升级给用户。⛔ **联系不上不构成动别人文件的授权。**
    **下次什么时候会用到**：往任何交接文件里写「如果 X 不行就用 Y」的时候；以及联系不上某个窗口、想改成自己动手的时候。

39. **⭐ 我的公式是对的，散文是松的——验证力气要照这个分布放（2026-08-15，一次独立复核的六处修改全部落在同一侧）**：那次复核确认**三段推导全部正确、全部数字与页面图像逐格相符、伪代码逐步对得上**，而六处修改里五处是散文与转述：把「三个控制器只在一种情形下才分得开」写成了实际上三种情形都分得开；把论文**有条件的**拒绝（「**可能**需要无限记忆……**若如此**则」）写成了一律拒绝；把一处排印错误的位置说错。
    **为什么会发生**：公式我逐条回了 170–450 dpi 的页面图像，因为「公式会被文字层吃掉」这条纪律逼着我做；**散文没有对应的纪律，于是全靠印象**，而印象最容易把「有条件」压成「无条件」、把「其中一种情形」压成「唯一情形」。
    **规则**：转述**限定语**（可能/若/其中之一/大多数/在某条件下）时，把那一句也当公式办——回原文逐字读一遍再写。⚠️ 判别信号：自己写出的句子比原文**更干脆**，那多半是丢了限定语，不是写得更清楚。
    **下次什么时候会用到**：写任何转述性段落时；尤其是写「论文的局限」那一节，因为把作者的保留写成绝对，会把一个诚实的作者写成一个粗糙的作者。

40. **⛔ 这个库的提交记录分不出是哪个窗口做的——所以"谁提交的"这个问题根本查不出答案，不许推断（2026-08-15）**：多个并行会话都以同一个人、同一个邮箱提交，作者字段完全一样。有窗口从"某某今天说过在改这个文件"推出"那次提交是它做的"，向我发了指认；**我查记录反驳后，它再查那次提交的差异内容，发现新增的六行里有五行是它自己写的、只有中间一行是第三方写的，而提交信息描述的正是那一行**——所以真相是第三个窗口写了那条并提交，顺手把它当时还没提交的四行一起带走了（它自己那次提交因此报"没有可提交的改动"）。
    **两层教训**：①**"查不出来"不等于"可以推断"**——发指认之前手上就有一条能直接查的证据（那次提交改了哪些行），没查就发了；②归因要靠**内容**不靠**时序**：谁写的看那几行像谁的文风与主题，比"谁今天说过要改这个文件"可靠得多。
    **配套动作（正面做法，比只说危险有用）**：动共享文件之前先看一眼 `git status`；要么等对方提交，要么带走时**在提交信息里写明带了谁的什么**——这样历史上就看得见。⚠️ 共享文件上按路径提交，拿的是**工作区当时的内容**，不是"你以为你改的那些行"，本环境没有逐块选择提交的办法。
    **下次什么时候会用到**：任何要说"某某窗口做了某事"的场合；以及任何多窗口共享同一个仓库、同一个身份的项目里，凡想按来源追责或归因时——**先问这个问题在这个仓库里可不可答**。

41. **⭐ 撤回一条通知，不等于解除用户亲口下的限制（2026-08-15，同伴做对了，值得学）**：我误把停工通知发给了三条实验线，用户纠正后我发了撤回，写的是"照常干活、你自己的判断照旧是权威"。其中一条实验线回话说：**约束它的从来不是我那条通知，而是用户当面下的令**（额度用尽、跑完只把结果存下来、不做任何决策、等他那边恢复），所以我的撤回对它净效果为零，而且**它不能把我的撤回当成放行——放行只能由用户本人开口**。
    **为什么值得记**：撤回一条自己发出的错误指令是对的，但**撤回的范围只能是"我加的那部分"**。我那句"你自己的判断照旧是权威"读起来像是把决定权整个交还给它，而它头上还压着用户的限制——**如果它照字面理解，就等于我替用户放行了**。同伴顶住了这一点。
    **规则**：撤回或放宽任何限制时，明确说清**撤的是我加的哪一条**，并且写明"用户原有的限制不受影响"；⛔ **绝不用"你自己定"这类总括说法去收尾**，除非确认对方头上没有别人的限制。

42. **⛔ 按「东西放在哪」去认，永远会漏掉下一条没人告诉你的路径；按「东西是什么」去认才不会（2026-08-18，一天之内同一个判定错了两版）**：查书工具要回答「这本书的文本能不能用来引用」。**第一版**写死一份「纯图像、搜什么都返回零」的书单——**无声过期了五天**（那批书早就做过文字识别、能搜了；名单的注释里甚至已写着其中两本"已退役"，另外五本却留着，读的人分不出哪半可信）。**第二版**改成「看识别产物目录里有没有」——**当天就漏**：另有一条流水线把书切块放在别处，那条路上的书一本都认不出来。**第三版**才对：**直接问那两个对象本身**——PDF 抽样几乎没字、而文本文件是满的，那这份文本就是识别来的。
    **判据的形状**：前两版问的都是「它在哪个名单里 / 它在哪个目录下」，那是**关于世界的一个可变事实**；第三版问的是「它本身是什么样」，那是**对象的属性**。前者要靠人记得同步，后者不用。
    **同族的第二例（同一天，另一个窗口自查出来的）**：某个页面的来源字段挂了三本书，实际只用到两本——页面上还专门写着"本页不依赖第三本"。**但那一行同时是自动生成「哪本书已被用过」那张表的输入**，而那张表存在的目的正是防止后来的读书计划把写过的章节重挖一遍。**名字挂在那里，表就会声称这本书被用过，而所有机械检查全绿。** 凭据本身写错，比内容写错更难发现。
    **下次什么时候会用到**：写任何"哪些属于某一类"的判断时——先问这份名单**靠谁去同步**，如果答案是"靠人记得"，就改成从对象本身算。以及**写任何会被别处当输入的字段时**（来源、标签、状态），先问"填宽了会让哪张表说谎"。

43. **⛔ 中转目录不许出现在任何长期记录里（2026-08-18）**：用户传文件进来的 `~/upload/` 是个**中转区，处理完就清空**。当天有一张卡的记录把它当成了全文来源路径写进去——**几小时后那个文件就会随清理消失，而记录仍然指着它**，下一个人按图索骥只会扑空，且看不出是文件没了还是路径写错了。
    **规则**：从中转区拿到的东西，**先移进永久位置再引用**，并且**把关键属性写进文件名本身**（比如版本：`..._PUBLISHED.pdf`）——这样即便记录丢了，文件自己还说得清自己是什么。
    **下次什么时候会用到**：任何时候要在文档、记录、队列行里写一个路径——先问"这个目录会不会被清"。

44. **⛔ 只以「示例」形式存在的规矩，挡不住任何人——而且它被绕过时不会有任何动静（2026-08-18，用户肉眼发现，已漂了一个多月）**：房规里概念页的结构模板从元数据**直接进提示框**，没有一级标题（理由是 Obsidian 已经把文件名显示为标题，再写一遍是重复）。**但模板只是展示了正确的样子，从没有一句话说「不许加标题」。** 于是按通常的 Markdown 习惯写页面的人加了一个，觉得完全正常，也没有任何检查看得见——**全库 1943 页概念页里漂出 256 页，其中 234 页的标题与文件名一字不差**。没有人违规，也没有人发现。
    **规则**：**规矩要么是明文加检查，要么等于不存在**。写下任何"应该长成这样"的模板时，同时问一句：**如果有人多加了点什么，谁会发现？** 答案是"没人"就当场补明文，并配一个能报出来的检查。
    ⭐ **配套的第二问，同样重要**：立禁令之前先问**这个东西有没有正当用途**。本例里 256 页并非全错——**其中 10 页的标题在承载文件名装不下的东西**（文件名写不了数学记号和正确的连接号：某页文件名只能写 `Convergence in Lp`，标题写的是排版正确的 $L^p$）。所以检查的判据定成了**判「与文件名重复」而不是判「存在」**。**一刀切的禁令会把这类真需求一起杀掉，而被杀掉的信息不会有人来提醒你。**
    **下次什么时候会用到**：写或改任何模板、样例、"标准写法"时；以及发现一处偏离、想立刻禁掉它的时候——先数一数这类东西里有多少其实是对的。

45. **⛔ 半扫描比空扫描更阴：它有输出，而那份输出看着完全正常（2026-08-18，我装检查时自己栽的）**：新写的检查算库根路径时**少数了一层目录**，于是它去扫了一个子目录而不是整个库。**全库 192 处违规，它报出 1 处**，格式、措辞、退出码全都正常——**我是因为这个数字与我十分钟前手工数的对不上才发现的，否则它会一直"通过"下去**。
    **与既有规矩的关系**：防自欺规矩第 8 条已经要求"门要自证输入非空"，**但那一条防的是「扫到 0 个」**；这一次是**扫到了一些、只是远远不够**，而"一些"看起来比"零"可信得多。
    **修法**：检查要**自证扫描规模**——把"本次扫了多少个文件"与该仓库的已知量级比一次，**低于量级就直接报错**，而不是打印一份看着正常的报告。本例落地成"扫到的页面数少于 500 就报错并打印它当前认定的库根路径"。
    **下次什么时候会用到**：任何新写或改动扫描范围的检查；以及**任何时候一个检查报出的数字比你预期的小**——⛔ 别先高兴，先问它这次到底扫了多少个东西。

46. **⛔「没有任何检查能发现这一类」通常是「我没想出判据」的伪装（2026-08-18，同伴当场认下的一条，值得所有窗口学）**：概念窗口报回一类缺陷——页面许诺了未来的工作，工作做完却没人回头改那句话——并断言「没有任何机械检查会提醒」。**当场就写出来了一个**：判据是「句子里出现『另占一页』这类交接说法，而同一句里没有任何链接」，全库 2340 页只报 3 处，三处都是真的，其中一处正是它自己一小时前那次编辑漏掉的后半句。同伴事后自己认得很准：**它把「现有检查看不见」误当成了「这件事查不出来」**。
    **两者的区别是实打实的**：前者是关于**已有工具**的陈述，通常为真且容易验证；后者是关于**可判定性**的陈述，要强得多，而且几乎从来没人真去论证过。把前者说成后者，等于给「不做」发了一张永久免检证。
    **⭐ 为什么这类判据经常存在而没人想到**：现有检查往往在验证**已经存在的对象**（链接指没指向真东西、公式渲不渲得出来），而这一类缺陷恰恰是**某个对象压根没被创建**——检查一个不存在的东西当然无从下手。**换个问法就有了：不要问「这个东西对不对」，问「有没有一句话在断言某个东西存在」**，然后去核那个断言。同族＝第 42 条（按「东西是什么」去认，而不是按「东西放在哪」）。
    **下次什么时候会用到**：任何人（包括我自己）说出「这个只能靠人看」「机械检查抓不到这一类」时，**先花两分钟试着把它写成判据再下结论**。判据写不出来是允许的结论，但它必须是尝试之后的结论，不是代替尝试的说法。

47. **⛔ 同一件事实在一个文件里写了两遍，你只会更新其中一遍——而且改的人是最不容易发现的那个（2026-08-18，一小时内两个窗口各栽一次，形状完全相同）**：概念窗口改一句话，**前半句改了、后半句原样留着**，那半句从此说的是假话。一小时后我改库的操作规则文件，把「不 push 用户就看不到」判成危险的过期说法、重写了开头那一段，**而那句话本身在同一个文件第 14 行原封不动活了下来**，是同伴读出来告诉我的。
    **机制**：改的人**记得的是自己改过的那半**，重读时脑子里放的是新版本，于是旧的那半读上去毫无异样。别人没有这份记忆，反而一眼就撞上矛盾。**所以这一类不能靠自己重读发现，只能靠机械搜索或者别人读。**

  我数「库里有多少句『此事已登记在某文件』」，得 **8 处**，据此判「太少，不值得做成脚本」。

  ⚠️ **最该记的是它的形状**：**那个错数指向的结论（不值得做脚本）是对的**，
  ⛔ **所以没有任何力量会让我回头去核它**——**一个数错了、而结论仍然成立的判例，正是最容易被放过的那种**（同一条今天已经出现两次）。

- **⛔⛔ 扫描件会凭空造出「原文自相矛盾」，⚠️ 而看到矛盾时的本能是去调和它——调和一个不存在的矛盾，产出的是编造（2026-08-22）。**

- **⭐⭐ 把上一条推广成一族：读者替原文做的三件事，每一件读起来都像尽责，而产出都比原文更完整、更好用、也更假（2026-08-22 一天之内三件全中）。**

- **⭐ 「祛魅型」产物有固定的失败方向，2026-08-21 至 22 三天连中三次，已可当作必查项而非观察项。**

    ⚠️ 这一条还有个尾巴值得记：我当时的理由是「修了也只绿一小时，下一次定时任务又会把它写回去，那等于我报了『已修好』而它自己会悄悄变回红的，比不修更坏」——**这半句是对的**，问题不在「先别动手」这个判断，而在我给出的**无害理由**是编的。**「现在不该动手」和「这件事无害」是两个独立结论，凑在一起说会让前一个替后一个背书。**

## 禁用「估计顶替账本」（2026-08-30，两窗口各半教训的合订）
同一类错的两个案例：①交接便条 updated 字段凭印象填了未来时间（被同伴抓）；②把队列里 3 个别窗口的作业凭「数量对得上」认领成自己的遗留并建议用户取消（误杀，被物主窗口抓）。**Why**：归属、时间、完成状态这三类判断都有权威账本（`~/jobs/.map.tsv` 反查作业真名、系统时钟 `date`、sacct/结果文件），估计只在没有账本时才允许出场。**How to apply**：要写时间先跑 date；要认领/取消作业先反查映射表，查不到=不是自己的、不许动；要报「已完成」先看结果文件不看排队印象。相关：[[coordinator-verifies-subordinates]]、[[job-privacy-masking]]。

59. **⛔⛔ 比较级与最高级是最容易朝自己论点方向说错的一类句子，而独立复核往往结构性地抓不到它（2026-09-04，同一轮里第三次犯）**：判例都是读论文建卡时写的比较句——①某张卡写「外圈里没有第二篇这么明确」与「最可引用的一处」，而被比的那篇论文自己就有更明确的一句、**库里那张卡早已记着它**；②另一张卡写「唯一做过这件事的」，而同批另一篇也做过；③最近一次写「这一篇比 MOPO 更干净——MOPO 只是把可容许性写成假设，而这一篇是作者自己说出来的」，**回库核 MOPO 那张卡，MOPO 也是自己说出来的、说了四处，而且还多跑了一个把启发式换成真预测误差当惩罚的消融**。三次的方向完全一致：**都朝着让本项目的论点更好看**。

    ⭐ **这一条真正新的地方是它为什么防不住**：前两次是独立复核抓到的，第三次**复核抓不到**——它的任务书给的是被评论的那一篇及其补充材料，**被比较的那一篇不在它的材料范围内**。它诚实地把那条标成「在我的材料范围内无法验证」，然后我才回库自查发现是错的。**所以「派了复核」并不覆盖比较句**：复核看的是一份材料，而比较句的真值住在两份材料里。

    **规则**：⭐ **凡在产物里写下比较级或最高级（更/最/唯一/第一个/没有第二处/比 X 更 Y），落笔前回库打开被比较的那张卡或那份摘要读一遍**，一次 grep 加一次 Read 的代价。⛔ **不许凭「我读过那篇、我记得它没有」**——三次判例里有两次，库里恰恰记着相反的内容，而记着它的正是我自己先前写的卡。

    ⚠️ 同族但不同源：**规则 40**（转述限定语要回原文，判别信号是「自己写的句子比原文更干脆」）管的是**一份**材料内部的失真；这一条管的是**跨材料**的失真，判别信号是「这句话让我方的论点显得更独特」。**How to apply**：写完一段产物，先把里面所有带比较意味的词圈出来，逐个问「被比的那个对象，库里有没有页面？」有就打开读；没有就把句子降级成只描述本篇的陈述。相关：[[audit-attribution-when-writing-paper-notes]]、[[attribution-verify-relayed]]。

60. **⛔⛔ 同一个偏向的第二种形态：把论文的某个部件挂到错误的分支上（2026-09-04，两天内第四次朝自己论点偏）**：判例——某篇统计论文的补充材料到手后，我写「**假设层面编码了与结论层面同一个要求**」，并写「分箱方案觉得稀疏的那块区域，**正是**那条非退化条件快要失效的方向」。⛔ **两处都错**：①把**系数空间里的一个单位方向**（与对协变量空间的任何划分无关）与**协变量空间里的一块区域**混为一谈；②**四条假设全部住在核函数类与 Lipschitz 类的证明节里，而项目关心的那条区域条件推论一条都不用**——证明主覆盖保证那一节内 Assumption 零命中（同段 Theorem 命中 12 次、Proof 命中 3 次，检索有效）。

    ⭐ **这一次的机制与第 59 条不同，所以要单列**：第 59 条讲的是**写比较级而没回库核被比较的对象**（跨材料）；这一次**没有比较任何东西**，而是**在一份材料内部把部件接错了分支**。共同点只有偏向：四次的方向全都是让本项目的论点更好看。

    **规则**：⭐ **凡把论文的某个部件（假设、引理、实验、限定语、常数）与本项目的某个关切挂钩，落笔前先查那个部件在原文里服务于哪一条结果**——把它每次出现的页码列出来，再对照该文档的分节起止，看它落在哪一节。⚠️ 判别信号：自己写出的句子里出现「正是」「同一个」「不过是……的另一说法」这类**把两个不同层级的东西等同起来**的连接词。

    ⭐ **附带的好消息，值得记住以降低这类冲动**：这次改正之后的说法**比错的那版更有用**——区域条件那条推论是该论文假设最轻的一端，于是「这个构造已被预先做过」变成了「而且是被在代价最低的那部分预先做过的」，对稿子更有价值。⭐ **朝自己有利的方向说错，往往是把一个更好的事实换成了一个更弱的假事实。** 相关：[[audit-attribution-when-writing-paper-notes]]。

61. **⛔⛔ 「这件事系统里存着、一条命令就能查」——而我却是凭知道的东西造出来的（2026-09-04，读论文窗口一天内七次，两种形态）**：形态一是**造标识符**：我知道一篇论文的题名，而库里的文件名是从题名派生的，于是我**生成**了一个文件名而不是去查。一天里造错五次（三个摘要文件名、两个知识库页面名）。形态二是**造引用关系**：我读了 A、也读过 B、两篇主题相邻且都在库里，于是写下「A 引了 B」。⛔ **两条都是假的**——其中一篇根本不在 A 的参考文献表里，A 那句话引的是另外两篇。

    ⭐⭐ **这一条真正值得记的不是「要查」，而是两种形态的被抓概率差了一个数量级，而这恰恰让人学不会**：造错的文件名会立刻变成一条指不到的链接，**链接检查当场报红**，所以五次全被拦下、五次都是十秒钟改完。造错的引用关系**没有任何机械检查能发现**——它是一句语法通顺、主题贴切、看起来像在陈述事实的话，只有让人去翻 A 的参考文献表才能推翻。⚠️ **于是我在被机械拦下五次之后，仍然犯了那两次没人拦得住的。被拦住的那五次没有教会我任何东西，因为它们不疼。**

    **规则**：⭐ **凡要写下一个标识符（文件名、页面名、条目号）或一条关系（A 引了 B、A 定义了 X、X 出自 Y），先跑那条能定它的命令，再落笔。** 具体两条：标识符用 `ls | grep` 或 `find -name`；引用关系去 **A 的参考文献表**里搜 B 的 arXiv 编号或 DOI——⛔ **不许搜题名**（题名会改版，本轮就撞上一篇改过两次题名的），也不许凭主题相近推断。

    ⚠️ **判别信号**：一句话里出现「X 引了 Y」「X 就是那篇讲 Z 的」「这是 Y 的出处」，而我**没有在这一回合里打开过 X 或 Y**。⭐ **代价对比是这条规则的全部说服力**：查一次是一条命令；写错一次，是把一句关于某篇已发表论文的假话放进一个会被读很多年的库，而且**没有任何自动检查会在将来把它找出来**。

    ⭐ **附带的一条方法**：判「A 引没引 B」时，**去 A 的参考文献表搜 B 的编号**这个做法，比读 A 的正文可靠得多——本轮有一篇全文搜 `Nash`、`equilibrium`、`zero-sum` **全是零命中，却确实引了 Nash averaging 那篇**，因为它**只按作者姓名引**。⛔ **正文里搜概念词得到零命中，不能推出「它不碰这条线」。** 相关：规则 48（阴性结论的范围）、规则 59（比较句要回库核）、规则 60（部件挂错分支）。
