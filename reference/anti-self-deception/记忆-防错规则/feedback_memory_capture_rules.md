**来源**：2026-07-22 采自 wanshuiyin/ARIS `shared-references/capture-antipatterns.md` + `tools/capture_filter.py`（调研台账 [[awesome-claude-code-survey]] 07-21 批）。机械筛=`check_memory_refs.sh` R6（INFO 级只列候选，周巡分诊）。

**Why**：负面能力断言一旦入 memory 会固化成拒绝——问题早修好了，agent 还在几个月后引用旧账拒做。直接命中 2026-07-17 Assignments 事故病灶（编造「Bash 管道污染」入账掩盖真错误，见 [[no-env-scapegoating]]）。

**How to apply**（写任何 memory 前对照四类禁存）：

1. **环境特异失败当全局真理存**——「X 在 Y 机器上挂了」不许写成「X 不能用」；要存就带环境限定词与日期。
2. **瞬时错误**——网络抖动、一次超时、一次 429 不入账；复现 ≥2 次且有最小复现证据才可记（与 [[no-env-scapegoating]] 的先复现后声称同构）。
3. **负面工具能力断言**——禁存「X 干不了 Y」裸断言；**改存修法/绕过/替代**（例：「本机无 pdflatex→结构性 grep + Overleaf 渲染」是合法写法，因为存的是 workaround 不是 can't）。
4. **单例叙事**——一次成功/失败的孤例不许总结成规律；标「n=1 待复验」或不存。

- R6 只能筛「同行无修法词」的强负面断言候选，判死一律人工；已带 修/绕过/改用/替代/workaround 字样的行不报。
- 已有存量若被 R6 或人工发现违规：补修法或删条目，不留裸 can't。

## 证伪与时效判定（2026-07-22 采自 <collaborator>/MAMA 补扫，出处 [[awesome-claude-code-survey]]）

- **判某条 memory 被证伪前过两问**（<collaborator> 归因七规则精髓）：① 这次失败是否**确实依赖**了该条内容（echoed/relied，仅同话题不算）；② 错在条目内容本身，还是执行没照做/环境因素——**没照做 ≠ 条目错**（本文件是「禁甩锅环境」的对偶：那条防把错推给环境，这条防把错推给 memory 而删掉好规则）。存疑一律不动条目。
- **一次实锤误导 > 多次成功战绩**：某条被证实误导过一次，当场重写或降级，不许用「它以前一直管用」对冲；反向同理，一次成功不升定律（与四禁存之单例叙事同源）。无明确信号（用户裁定/复现证据）不算「验证通过」。
- **时效判快照不判指针**：memory 条目若是对某对象的**快照式陈述**（数字/结论/状态），巡检时看锚定物（文件/LEDGER 节）是否在该条更新**之后**又动过——上游动了=待回源，比日历龄准；若是**指针式**（「单源在 X」），上游常动是设计本义，不算过时。机械化不划算（指针型占多数会全是噪音），留作 /kb-audit 人工分诊判据。

## 跨文件状态快照禁令（2026-08-14，候选 D <project-B> 状态答错事故后立规）

**事故**：候选 D 的对抗审稿收敛状态在项目档案里 08-12 已更新为「条件收敛」，但审稿方法论文件里 08-11 写的「D 待复核」快照没人回改；两天后我引用旧快照把用户答错，用户凭记忆纠正后才查出真相。**病根=同一事实写在两处，进度只推了单源，副本静默陈旧**——每日 memory 状态检查只对索引行/描述字段，正文里指向别的项目的状态断言在盲区。

**规则两条**：
1. **写入端（根治）**：在 A 文件里提及 B 项目的状态时，一律写**指向 B 单源的指针**（「查 X 状态以 project_xxx.md 为单源」），不写状态快照；确需快照（如对比表）必须带日期戳+「以单源为准」字样。
2. **更新端（兜底）**：更新任何项目的状态时，同回合 `grep -rl "<项目名/代号>" memory/` 扫其他文件的提及处，发现旧状态快照就当场改成指针。一条 grep 的成本，防的是跨会话的假情报。

**Why**：memory 的读者（下个会话的模型）无法分辨快照新旧，陈旧快照比没有记录更危险。**How to apply**：见上两条；违例先例=feedback_review_self_audit.md 的 D 追溯行（已改为指针）。
